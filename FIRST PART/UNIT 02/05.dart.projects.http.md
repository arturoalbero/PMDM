# Dart Projects

So far, we have developed Dart programs consisting of a single file, which we executed using the `dart` command-line tool.

When our program grows and we need to divide its functionality across several files, we need to create a complete *Dart* project, allowing us to specify third-party library dependencies and additional configuration options. To do this, we will use the `create` subcommand of the `dart` command.

If we run `dart create` directly, we can see the different options it provides. In our case, and as an example that we will continue working with in the next section, we will create a simple console project called `example_project`.

**Project Names**

In Dart, all folders (including the project folder) and files use *snake_case*: they always use lowercase letters, with underscores to separate words.

For example, if we have a class called `MyClass`, the file containing it will be called `my_class.dart`.

To create the project, inside the folder where we want to create it, we will run the following command:

```bash
$ dart create -t console-simple example_project
```

This will generate the usual Dart project structure inside the *example_project* folder. The most relevant elements for us are the file containing the project properties (*pubspec.yaml*) and the directory containing the source code (*bin* in the case of Dart).

**Note**

If we inspect the generated folder, we will see that it contains the following:

```text
example_project
├── analysis_options.yaml
├── bin
│   └── example_project.dart
├── CHANGELOG.md
├── pubspec.lock
├── pubspec.yaml
└── README.md
```

In addition to the `pubspec` file and the `bin` folder, we find a file for change tracking (changelog), a `README` file, and a `.gitignore`, among others.

**Note**

When working with Flutter, we will see that the project structure is very similar, since a Flutter project is also a Dart project. The main difference we will find is that the source code is located in the `lib` folder instead of `bin`.

## Packages and Libraries: The `pub` Package Manager

Dart uses *packages* to manage shared software, such as libraries or other utility packages.

The package manager used by Dart is `pub`, which allows us to load packages from the local file system or from *Git* repositories. However, we will generally use the public package repository, *pub.dev*. The *pub* package manager is also responsible for managing and downloading dependencies between packages, taking the SDK version into account.

Most IDEs that support Dart provide support for using *pub*, allowing us to create, download, update, or publish packages. VSCode allows us to interact with the *pub* system through the *Dart* extension, as well as add new dependencies using the *Pubspec Assist* extension.

**Dart Packages**

A Dart package is a directory that, at a minimum, contains a `pubspec.yaml` file. This file contains metadata about the package, as well as the list of dependencies, libraries, tests, or any other type of resource.

To add dependencies to a project, we can edit the *pubspec.yaml* file directly, or use the `dart pub add` command.

For example, we will add the dependency on the [http library](https://pub.dev/packages/http) to the *example_project* project. We will use it in the next section, and it is responsible for making and managing HTTP requests to the web. We have several options for doing this:

* **Option 1. Add the library from the command line**

From inside the project directory, we would run:

```bash
$ dart pub add http
```

This adds the following line to the `pubspec.yaml` file, inside the `dependencies` section:

```yaml
  http: ^0.13.5
```

* **Option 2. Modify the** ***pubspec.yaml*** **file directly**

Another option is to add the dependency directly to the `pubspec.yaml` file in the dependencies section:

```yaml
dependencies:
  http: ^0.13.5
```

* **Option 3. Add the dependency using the Pubspec Assist extension**

From VSCode, we can add the dependency using the Pubspec Assist extension. To do this, we open the VSCode command palette (`Ctrl + Shift + P` on GNU/Linux and Windows, or `Command+Shift+P` on Mac) and search for the command *Pubspec Assist: Add/update dependencies*.

If we are in a directory containing the *pubspec.yaml* file, it will ask us which extension we want to install. We enter `http`, and the dependency will automatically be added to the file.

### Downloading Libraries

When we add a dependency from the command line (using `dart pub get`), or if we edit the *pubspec.yaml* file in VSCode, regardless of how we edit it, the package is downloaded automatically.

If we have modified the file using another editor, or if we have obtained a project whose dependencies have not yet been downloaded, we can download and install them manually using the `dart pub get` command (in Flutter, we will later use `flutter pub get`):

```bash
$ dart pub get
Resolving dependencies... 
Got dependencies!
```

**Where Are the Libraries?**

As indicated in the [official Dart documentation](https://dart.dev/tools/pub/cmd/pub-get#the-system-package-cache), unlike other platforms such as Node.js or Java, dependencies are not stored in the project itself, but rather in a system package *cache*.

The idea is that, since several packages may use the same version of a dependency, it only needs to be downloaded once and can remain stored in this system cache.

If we examine a Dart project, we will see that there is a hidden directory called `.dart_tool` containing a `package_config.json` file. This file contains information about the libraries required by the project, their versions, and the location where they can be found in this *cache*. The most common location for this is the `~/.pub-cache/hosted/pub.dartlang.org/` directory in our home folder.

# The [HTTP](https://pub.dev/packages/http) Library

In the previous section, we already saw how to add the HTTP library to our project, which will allow us to make HTTP requests to any network resource, using *Futures*.

The HTTP library internally defines a set of high-level classes and functions for consuming HTTP resources, such as the `get()`, `post()`, `update()`, `put()`, and `delete()` functions, among many others.

The simplest way to use the library is to import it into our code with:

```
import 'package:http/http.dart';

```

and directly use these high-level functions (not associated with any object).

Another fairly common option is to define a namespace as an *alias* under which to reference the entire library. To do this, we import it as follows:

```
import 'package:http/http.dart' as http;

```

This way, we access the functionality provided as if it were methods of the *http* namespace: `http.get()`, `http.post()`, etc.

### Example 1. Processing with Futures

Let's look at the following code to see how we would use the HTTP library to make requests and process responses with *Futures*:

```
// Import the necessary libraries
import 'dart:convert'; // To perform conversions between data types
import 'package:http/http.dart' as http; // To make HTTP requests

void main(List<String> args) {
  // Define the endpoint or resource address:
  String url =
      'https://healthys-express-backend-production.up.railway.app/api/entrants';

  // And make a GET request using the http.get method:
  var response = http.get(Uri.parse(url));

  // This returns a Future, which must be processed
  // using the then method:
  response.then((data) {
    // The Future completes with an instance of the Response object
    // which contains a statusCode property with the status code
    // and a body property with the response body.

    if (data.statusCode == 200) {
      String body = utf8.decode(data.bodyBytes);
      final bodyJSON = jsonDecode(body) as List;

      // And display it
      print(bodyJSON.toString());
    } // if
  });
}

```

If we now run the project with `dart run`, we will obtain the list of starters in JSON format.

Although you already have the comments in the code, let's make a few points:

* Notice that we have imported two libraries: *convert* and *http*. The *convert* library is a standard Dart library, so we did not have to download it. To indicate that it is a standard library, we put `dart:` before it. On the other hand, the HTTP library has been downloaded as a package, which is why we put `package` before it when importing it.
* When we make the GET request (`http.get()`), a *Future* is returned, which we process with `then`. The `Response` object to which this *Future* resolves contains the status code of the HTTP request (`statusCode`). When this code is *200 (OK)*, it indicates that the request was handled correctly and therefore the response is available in the `body` property. This code can also indicate errors in the request (4xx, such as 404 Not Found), or internal server errors (5xx).
* To decode the JSON returned in the response, we did it in two steps. First, we decode the response in UTF-8 format to decode special characters:

```
String body = utf8.decode(data.bodyBytes);

```

Then, we decode the resulting String as JSON and cast it to a list:

```
final bodyJSON = jsonDecode(body) as List;

```

* If we obtained this `bodyJSON` without first decoding it as UTF-8 (`bodyJSON = jsonDecode(data.body) as List);`, strange characters would appear instead of accented characters.

**About UTF-8 Encoding**

With recent versions of Dart, `response.body` usually handles UTF-8 encoding correctly. However, this conversion will be useful when incorrectly encoded special characters are received.

# Example 2. Processing with async/Await

In the previous example, the HTTP response is returned asynchronously as a *Future*. An alternative, if we do not want to work with callbacks using `then`, is to make the request with `await` and wait for it to complete:

```
var response = await http.get(Uri.parse(url));

```

Here, instead of a `Future`, the `response` variable would directly contain the response.

On the other hand, this would require us to define the `main` function as `async`.

Therefore, the complete code would be:

```
// Import the necessary libraries
import 'dart:convert'; // To perform conversions between data types
import 'package:http/http.dart' as http; // To make HTTP requests

void main(List<String> args) async {
  // Define the endpoint or resource address:
  String url =
      'https://healthys-express-backend-production.up.railway.app/api/entrants';

  // And make a GET request using the http.get method, with await:
  var data = await http.get(Uri.parse(url));

  // Here we already have the information in data, so we process it as before

  if (data.statusCode == 200) {
    String body = utf8.decode(data.bodyBytes);
    final bodyJSON = jsonDecode(body) as List;

    // And display it
    print(bodyJSON.toString());
  } // if
}

```
