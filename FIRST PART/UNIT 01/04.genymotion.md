# Introduction. Emulators

If we want to create applications for other platforms, we will need tools that facilitate the emulation of devices for running and testing software. Genymotion is an environment that facilitates the testing and development of Android applications and is available through three different solutions:

* **Device Image**, a *pay-as-you-go* solution that allows Android virtual devices to be used within a web browser, scaling the environment according to requirements. It is a *Platform as a Service (PaaS)* solution, with Genymotion hosted by *cloud* providers such as Amazon, Google, Alibaba, Azure, or Oracle.
* **SaaS**: Genymotion's *Software as a Service (SaaS)* solution, which provides enterprise collaboration features to facilitate collaboration and automation throughout the mobile application development lifecycle, and allows testing to be optimized in a continuous integration environment.
* **Genymotion Desktop**: A cross-platform emulator specifically designed to emulate Android devices, including a complete set of sensors and features for interacting with a virtualized Android environment.

In our case, we are going to use this last solution in order to test our applications on a virtual device, as an alternative to the Android emulator. Genymotion Desktop requires a virtual machine hypervisor. Specifically, it supports VirtualBox and, experimentally, QEMU.

It should be noted that this is a paid solution, but it allows the use of a free license for personal use with certain limitations.

## Genymotion Desktop Installation

In the [official Genymotion Desktop documentation](https://docs.genymotion.com/desktop/) we can find different installation guides depending on our operating system. Let's look at the general steps that should be followed to perform the installation correctly.

### Step 1. Registration

First, we will need to register on the platform through the URL https://www-v1.genymotion.com/account/create/.

On this page, we will be asked for an email address and password for registration, as well as how we intend to use the platform and information about the type of organization:

[Genymotion Site Registration](https://joamuran.net/flutter2026/u1/img/4.genymotion/1.registre.png)

Once registered, we can access the website through https://www-v1.genymotion.com/account/login/.

[Login](https://joamuran.net/flutter2026/u1/img/4.genymotion/2.login.png)

### Step 2. Download and Installation

To download the Genymotion installer, we access [the download section of its website](https://www.genymotion.com/download/) and select the version corresponding to our system.

In our case, we will download the version for GNU/Linux, using [the installation guide in the documentation](https://docs.genymotion.com/desktop/Get_started/013_Linux_install/) as a reference.

**Be Careful with the Environment**

The Genymotion website itself provides some warnings regarding system requirements:

* It only supports 64-bit architectures and the Gnome, KDE, and Mate environments.
* It may cause problems with X11, so the use of Wayland is recommended.

[image](https://joamuran.net/flutter2026/u1/img/4.genymotion/advertencies.png)

However, many other factors also come into play, such as the graphics card, hardware acceleration, or the graphics drivers we have installed, so emulation may be slow or problematic.

In this case, [we can use physical devices to test our applications, either connected via USB cable or Wi-Fi](https://joamuran.net/flutter2026/u1/5.Dispositius/).

Once we have downloaded the installer, we need to give it execution permissions and run it. Assuming that we downloaded it to the *Downloads* folder, we access it:

```text id="49821"
cd ~/Downloads
```

We give it execution permission:

```text id="18463"
chmod +x genymotion-3.9.0-linux_x64.run
```

And we run it, specifying the installation directory (for example, `~/devtools`):

```text id="62754"
./genymotion-3.9.0-linux_x64.run -d ~/devtools
```

This will install *Genymotion* in the `~/devtools/genymotion` directory. To access the binaries from any directory, we will need to add this installation directory to the PATH. To do this, we edit the `~/.profile` file again and add the following code at the end:

```bash id="38572"
# set Genymotion Path
if [ -d "$HOME/devtools/genymotion" ] ; then
    PATH="$HOME/devtools/genymotion:$PATH"
fi
```

This will add the Genymotion directory to the PATH every time we log in. If we do not want to log out of the current session, we can reload the file in the current terminal with:

```text id="74613"
source ~/.profile
```

The main tools that *Genymotion* will have installed are:

* **genymotion**: The graphical tool for creating and managing our virtual devices.
* **gmtool**: A command-line interface for managing virtual devices.
* **genymotion-shell/genyshell**: An interactive *shell* for interacting with the devices' sensors.

**More information...**

More information about these tools can be found in the official Genymotion documentation:

* [Genymotion Shell](https://docs.genymotion.com/desktop/05_Genymotion_Shell/)
* [GMTool](https://docs.genymotion.com/desktop/06_GMTool/)

### Step 3. Configuration

The first time we launch Genymotion, we will need to enter the credentials we used to register on the platform:

[Initial Authentication](https://joamuran.net/flutter2026/u1/img/4.genymotion/First_time_opening.png)

**Warning!**

In some versions, it is possible that the application remains on the startup screen and does not proceed to request the credentials.

This is a [bug described in Genymotion's own documentation](https://support.genymotion.com/hc/en-us/articles/360009237638-Genymotion-Desktop-is-stuck-on-Booting-animated-logo), which can be resolved by entering the credentials manually.

To do this, we will close the Genymotion window and make sure that the process has not remained in memory (you can run `ps` and, if it still appears, use `kill -9` on its PID).

Once it is closed, we will use the `gmtool` tool to log in with our username and password:

```text id="51386"
./gmtool config --email my_email --password my_password
```

We can then launch `genymotion` again and access the main screen.

Once authenticated, we will be asked for the license. We will indicate that it is a license for personal use:

[License Selection](https://joamuran.net/flutter2026/u1/img/4.genymotion/3.PersonalLiscense.png)

We accept Genymotion's terms and conditions of use:

[Acceptance of the Terms and Conditions](https://joamuran.net/flutter2026/u1/img/4.genymotion/4.eula.png)

Finally, we will be asked for the path where the virtualized devices will be stored and which hypervisor to use (QEMU).

[Hypervisor Selection](https://joamuran.net/flutter2026/u1/img/4.genymotion/hipervisor.png)

Once this is done, the main window will open, from which we can start adding devices:

[Main Window](https://joamuran.net/flutter2026/u1/img/4.genymotion/princial.png)

As we can see, the sidebar contains different options for device management (Devices), images and hardware profiles (Android Images, Hardware Profiles), configuration (Settings), and Help (Troubleshooting).

### Step 4. Creating a New Device

#### Step 4.1. Choosing the Device

To create a new device, click the "+ Create" button. A new window will appear where we can choose which of several devices we want to emulate.

[Creating a New Device](https://joamuran.net/flutter2026/u1/img/4.genymotion/noudispositiu.png)

You can choose whichever device you want. Notice that each device is displayed as a row showing the type (mobile, tablet), name, screen size (*Display Size*), resolution, density, and source (*Source*) from which the images are obtained. At the end, an information icon is displayed, which will show some additional advanced options when hovered over, such as the number of processors, RAM, and storage allocated to the device.

In our case, we have chosen a Google Pixel 5, but in principle, you could use any device. Once selected, click *Next*.

#### Step 4.2. General Configuration

In the next window, we have several general configuration options. The most interesting one will be the Android version that we want to install on the device. We will choose Android 13.

[System Image Selection](https://joamuran.net/flutter2026/u1/img/4.genymotion/noudispositiu_1_general.png)

#### Step 4.3. System Configuration

The second configuration screen allows us to define some system settings, such as the number of processors, the device's memory, or the amount of memory that the JVM will reserve for each application. We should choose values that are within the capabilities of our computer, and then click *Next*.

[System Image Selection](https://joamuran.net/flutter2026/u1/img/4.genymotion/noudispositiu_2_sistema.png)

#### Step 4.4. Display Configuration

The next screen (*Display*) asks us to define some aspects of how the emulated device will be displayed, such as the device size, options such as rounding the edges, or whether we want the device to be displayed full-screen or in a window. We will leave all the default options and click Next.

[Display Configuration](https://joamuran.net/flutter2026/u1/img/4.genymotion/noudispositiu_2_sistema.png)

#### Step 4.5. Android Options

The fourth screen allows us to define some Android interface options, such as whether to display the navigation bar or whether we want to use a virtual keyboard for text input—if we do not select this option, we will use our computer's keyboard. We will leave the default options.

[Interface Options](https://joamuran.net/flutter2026/u1/img/4.genymotion/noudispositiu_4_options.png)

#### Step 4.6. Hypervisor Options

The final screen allows us to define how the device will connect to the network through the hypervisor, either using NAT (the default option) or Bridge mode (the hypervisor acts as a bridge and the device connects directly to the network).

[Hypervisor Options](https://joamuran.net/flutter2026/u1/img/4.genymotion/noudispositiu_5_hipervisor.png)

#### Step 4.7. Installation

Finally, click Install, and the system for the device will begin downloading:

[System Download](https://joamuran.net/flutter2026/u1/img/4.genymotion/noudispositiu_6.png)

Once it has been downloaded and installed, it will appear on the main screen, showing the device we have just installed.

If we look closely, we can see a line containing the information we already knew about the device: its name, Android version together with the API it supports, screen resolution, density, disk space used, the source from which the image was obtained, and an actions column. Under this actions column, we can start or stop the devices.

Therefore, to start the device, click the *"Play"* icon, represented by a triangle, at the bottom of the Actions section and wait for it to start. After a few moments, our emulator will be running. If we want to stop the emulator, under *Actions* we will now have the "Stop" icon, represented by a rectangle.

[Running Device](https://joamuran.net/flutter2026/u1/img/4.genymotion/EmuladorAndroid.png)

If we now run the `flutter devices` command, we will see that the device appears and can be used with our applications.

```text id="26497"
$ flutter devices
...

Google Pixel 5 (mobile) • 192.168.56.102:5555 • android-x64    • Android 13 (API 33)
```

### Updates

When a new version of Genymotion is released, it displays a notification at the top of the interface:

[Genymotion Update (Older Version)](https://joamuran.net/flutter2026/u1/img/4.genymotion/actualitzacio_genymotion.png)

If we click the corresponding download button, we will download the binary again, give it execution permissions again, and run it. When we do so, it will tell us that a previous version is already installed:

```text id="91246"
A previous installation already exists in folder [/home/joamuran/devtools/genymotion]. Overwrite [y/n] ?
```

We confirm that we want to overwrite it, and we will now have the latest version of Genymotion on our computer.
