# Connecting Physical Devices

Although Android emulators (both the one included with Android Studio and alternatives such as Genymotion) are usually very useful tools during development, we often need to use real devices to test our applications.

In this section we are going to see how to establish this connection and what settings we will need to configure, both on the device and in the development environment, in order to launch our applications on the real device.

**Why might it be interesting to use a real device?**

Using physical devices offers several advantages over emulators:

* **Better performance**, since apps run on real hardware, thus avoiding the overhead inherent to virtualization and possible performance or compatibility issues that may arise,
* **More realistic behavior**, since it allows access to sensors, camera, GPS, multitouch gestures, notifications, etc., as well as ensuring that graphical performance works exactly as it would in a production environment.
* **Avoiding emulator problems**, such as incompatibilities with virtualization, graphics driver issues, hardware acceleration, or specific operating system configurations.
* **Debugging under real conditions**: this is especially useful when errors are detected that only appear on specific devices or on specific versions of Android.

For all these reasons, it is very common to combine the use of emulators for initial development with the use of physical devices for final testing.

To establish the connection, we will use the **ADB (Android Debug Bridge)** tool to communicate with Android devices. This connection can mainly be established in two ways:

* **USB cable connection** (initially recommended)
* **Wireless connection (ADB over Wi-Fi)**

We will look at both options later, but first, let's focus on the settings required on the device.

## Android Device Configuration

Before we can connect any Android device to our computer, we need to enable some development options.

1. **Enable developer options**. Although each device model has its own peculiarities, the general procedure for enabling developer options on an Android system is usually similar to this:
2. **Step 1**. On the Android device, go to **Settings**.
3. **Step 2**. Go to **About phone**.
4. **Step 3**. Look for the **Build number** option.
5. **Step 4**. Tap **7 times consecutively** on this option until the system indicates that developer options have been enabled.

Once this has been done, a new menu called **Developer options** will appear in the system settings.

1. **Enable USB debugging**

Within the **Developer options** menu:

1. Locate the **USB debugging** option.
2. Enable it and accept the security warning.

This option allows the device to accept ADB connections from the computer.

## USB Cable Connection

This is the simplest and most reliable way to connect a physical device.

1. Connect the Android device to the computer using a USB cable.
2. On the device, accept the message **“Allow USB debugging from this computer”** (it is recommended to select the *Always allow* option).
3. Open a terminal and check that the device is detected correctly:

   ```
   $ adb devices

   ```

   If everything is correct, we will see output similar to:

   ```
   List of devices attached
   10HF8RFCUX000F4 device

   ```

**Note**

If we do not have the `adb` tool directly available, it is located inside Android's `platform-tools`. If we have installed the Android SDK in the `~/devtools` folder, it will be located at `/home/user/devtools/Android/Sdk/platform-tools/`. We can add this path to the *PATH* to access it more easily.

We can now also verify that the device is available from Flutter. To do this, type the following in the terminal:

```
$ flutter devices

```

The connected physical devices will be displayed. For example:

```
Found 3 connected devices:
  V2419 (mobile)  • 10HF8RFCUX000F4 • android-arm64  • Android 16 (API 36)
  Linux (desktop) • linux           • linux-x64      • KDE neon User Edition 6.14.0-37-generic
  Chrome (web)    • chrome          • web-javascript • Google Chrome 144.0.7559.96

Run "flutter emulators" to list and start any available device emulators.

```

**Warning**

If we cannot see the device from the computer, it is possible that:

* Either the cable we are using is a USB cable intended only for charging and does not allow file transfer,
* USB file transfer is disabled, in which case we will need to enable it:
![image](https://joamuran.net/flutter2026/u1/img/devices/fitxers_usb.jpg)

Now, in order to launch an application on the connected device, we will proceed in the usual way:

```
flutter run

```

If there is more than one available device (whether an emulator or a physical device), Flutter will ask us to choose which one we want to run the application on.

If we want to specify the device directly, we can do so with:

```
flutter run -d <device_id>

```

Where `<device_id>` is the identifier displayed by `flutter devices`.

## Wireless Connection (ADB over Wi-Fi)

Another option for connecting to a real device is through a Wi-Fi connection. To do this:

* The device and the computer must be connected to the same Wi-Fi network.
* USB debugging must be enabled.

Let's see how to establish the connection through the Android device manager.

1. Open the *Device Manager* tool from *Android Studio*, and look for the *Pair Devices Using Wifi* option.

![image](https://joamuran.net/flutter2026/u1/img/devices/pair_wifi.png)
2. Select it and, as we can see, we have two options: scan a QR code or pair the device using a code.

![image](https://joamuran.net/flutter2026/u1/img/devices/pair_qr.png)
3. To scan the code, on the device go to *Developer Options* > *Wireless debugging* (permission must be granted) > *Pair device with QR code*

![image](https://joamuran.net/flutter2026/u1/img/devices/qr.jpg)

With this done, if we check the devices again, we will see the one we have just configured.

With `adb`:

```
$ adb devices
List of devices attached
adb-10HF8RFCUX000F4-zpAMHs._adb-tls-connect._tcp        device

```

With `flutter`:

```
$ flutter devices
...

Found 1 wirelessly connected device:
  V2419 (wireless) (mobile) • adb-10HF8RFCUX000F4-zpAMHs._adb-tls-connect._tcp • android-arm64 • Android 16 (API 36)

```

We can now launch our applications with `flutter run` on the device.

**Some considerations about the Wi-Fi connection**

When connecting to the device via Wi-Fi, some details should be taken into account:

* It may be **less stable** than the USB connection.
* Latency is slightly higher.
* When restarting the device or changing networks, the process must be repeated.

Therefore, it is recommended to use it mainly in testing or demonstration environments.

## Device Mirroring

Once we have the device connected (either via USB or Wi-Fi), we have the possibility of displaying the device's screen and interacting with it from the computer. This way, we can demonstrate an application directly from a real device.

This is known as *device mirroring*, and the simplest, most efficient, and recommended way to do it is by using `scrcpy`: a free, cross-platform tool that allows us to mirror the screen of an Android device on the computer, with very good quality and low latency, using ADB underneath.

This tool has several advantages:

* It does not require installing anything on the Android device.
* It works with both USB and Wi-Fi.
* It has very low latency, making it ideal for live demos.
* It allows interaction with the device (clicks, keyboard, gestures).
* It consumes few resources.
* It works on Linux, Windows, and macOS.

Regarding the device requirements:

* It must be an Android device with USB Debugging enabled,
* The `adb` tool must work correctly, and `adb devices` must detect the device.
* It must be connected via USB or Wi-Fi, as configured previously.

### Downloading and Running `scrcpy`

Although the `scrcpy` tool is available in the official Ubuntu repositories, we are going to use the latest version, which supports connections to the most recent versions of Android.

To do this, [access the tool's download page](https://scrcpy.org/download/) and select our system.

![image](https://joamuran.net/flutter2026/u1/img/devices/scrcpy1.png)

For MacOS and Windows, we have compressed files containing everything necessary directly.

For Linux, we have a Github repository with the latest precompiled *releases*, so we download the file corresponding to our platform (**scrcpy-linux-x86_64-v3.3.4.tar.gz*), extract it, and run it:

```
$tar -xvzf scrcpy-linux-x86_64-v3.3.4.tar.gz 

$ cd scrcpy-linux-x86_64-v3.3.4/

$ ./scrcpy 

```

If we have several devices, we use the `-s` option with the device identifier:

```
$ ./scrcpy -s id

```

This tool also supports several configuration options, for example:

| **Command**                        | **Description**                                                 |
| ---------------------------------- | --------------------------------------------------------------- |
| `scrcpy -h`                        | Displays help with all available commands                       |
| `scrcpy --always-on-top`           | Keeps the scrcpy window with the device above the other windows |
| `scrcpy --stay-awake`              | Prevents the device from turning off during the demo.           |
| `scrcpy --max-size 1024`           | Reduces the resolution to improve performance                   |
| `scrcpy --show-touches`            | Shows touches on the screen                                     |
| `scrcpy --record demo_flutter.mp4` | Records the screen                                              |
